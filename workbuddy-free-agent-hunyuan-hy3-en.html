WorkBuddy Free Agent (Hunyuan hy3) — A Hands-on Review

By Tan Haosheng · Associate Chief Physician, MD/PhD · Thyroid & Breast Surgery, Taizhou People's Hospital

🔥 FEATURED 🆓 Free Tool Review 🤖 AI Agent

If you've wanted to use an Agent to automate weekly reports, write scripts, or organize data, but kept hitting two walls — "cost" and "environment setup" — this article is worth reading. Author Tan Haosheng treats Tencent's WorkBuddy (workbuddy.cn) as a "visual Agent orchestrator" with an optional Hunyuan hy3 model that is free for a limited time, with no usage cap; as long as your account credit balance stays above zero (credits can be claimed by completing tasks or daily check-ins), you can keep running a ¥0/month Agent.

I. What Is WorkBuddy? Positioning & Official Stance

Open https://workbuddy.cn — WorkBuddy's official self-introduction is direct:

WorkBuddy is Tencent's full-scenario AI office workbench. Tell it what you need, it starts executing tasks and delivers complete results. Seamlessly connected to Tencent's office ecosystem — your smart office companion.

Corresponding to S1 — the core area of the homepage:

Three key signals from this single screenshot:

  • "Full-scenario AI office workbench" — not chat-only, but a process product of "task → execute → deliverable", which fits mainstream office scenarios.
  • "Connected to Tencent's office ecosystem" — means direct integration with WeChat, WeCom, Tencent Docs, and ecosystem tools (very important for domestic office users, avoiding the "export then import" pain).
  • "Download / Use online" side by side — desktop client and web are the same product, consistent across devices. Friendly for users who need to "launch an Agent anytime, anywhere".

Author's note: Clear positioning, tightly bound to the local ecosystem — this is WorkBuddy's biggest differentiator from overseas tools like ChatGPT and Claude. If you already work in Tencent Docs and WeCom, the Agent's output drops straight into your existing workflow instead of being shuttled between systems.

II. Registration & Login: It Must Start with "WeChat"

After clicking "Log in" at the top-right of the homepage, a login chooser pops up — a large "WeChat Login" button in the center, with "Phone / Email / SSO" as secondary options below.

Three facts read from this screenshot:

  1. No "GitHub / Google third-party login" — a typical domestic account-system choice (phone/WeChat/email), friendly to local users but not to overseas readers, meaning the internationalization path relies on email or SSO.
  2. The red prompt "Please read and agree to the User Agreement and Privacy Policy" sits at the top — clear compliance intent, but you must check it before agreeing, a step that can't be skipped. One extra action for individuals, but good news for enterprise IT (easier to audit).
  3. SSO option exists — means the enterprise edition can plug into its own identity system; if teams adopt it later, accounts can be managed centrally. Ordinary users don't need it yet, but it's key to judging "can I deploy this for a team".

Author's note: The "WeChat login as the only primary" setting has two implications:

  • ✅ Convenient: domestic users register and log in within 3 seconds, zero friction.
  • ⚠️ Risk: the account itself is a "WeChat identity" weakly tied to a phone number; long-term, don't hang all your core Agents/tasks on the WeChat account alone — if the WeChat end gets banned/unbound (extreme case), recovery costs more than an email account.

So the advice: log in with a WeChat account you control; do not borrow someone else's WeChat or a temporary alt — the Agents, credits, and task data you generate later all travel with this identity.

III. Download & Install: Client and Web Dual-Track

Before logging in, return to S1 — note the top nav's Download button and the lower-half "Download now" button. Both lead to the same download page (screenshot S3).

This screenshot mainly shows three things:

  1. UI change before/after login — top-right changes from "Login" to a green user avatar, meaning login and download states are fully linked: you can download after logging in, or log in after downloading; both paths work independently.
  2. "Download now" and "Use online" coexist — means WorkBuddy doesn't force client installation. For users who just want to "try it once", clicking "Use online" for a zero-install trial run is the better starting point (avoids system-compatibility issues).
  3. Two redundant download entries (top "Download" button + in-page "Download now" button) — a common product convention to minimize the decision path.

Author's test: first step after login

After the author logged in on macOS, WorkBuddy's main UI has a "New Task" button at the top-left. Clicking it opens a task input box — you can either type a normal chat command for a one-shot Agent reply (like ChatGPT's chat-once mode), or publish a full task for the Agent to call tools in the background and deliver a usable result. This is a product simplification:

  • Chat = single-turn interaction, see the result right after input;
  • Publish task = drop the task into the Agent's "workflow"; it breaks steps, calls tools, and produces a file delivered to the task for you.

The key difference: chat costs fewer credits but is one-off Q&A; publishing a task costs more credits but runs multi-step and auto-delivers artifacts. The exact credit consumption rate(to be tested later) will be measured after the author actually finishes a task.

Concrete flow: log into the app → top-left New Task → type the task description → press Enter for chat / press the "Publish" button for a full task. §VI below demonstrates both usages.

Core mechanism (author's summary)

  1. "Free" means the underlying model (Hunyuan hy3) is free for a limited time with no usage cap — not billed per token, no per-call cap.
  2. The user must keep account "credit balance > 0". Balance hitting zero → account defaults to overdue status → calling the free model is immediately cut off.
  3. Credits come from two legs:
    • (A) Tasks: WorkBuddy's built-in "earn credits" task list (exact reward depends on the live page, since events change per round — must check "Growth Plan / Task Center" in-app for precision; author screenshots "Task Center" later).
    • (B) Daily check-in: this round fixed 100 universal credits / day (confirmed by S4 screenshot), a mindless click to claim; consecutive check-ins also give merch.
  4. Credits themselves are "universal credits", meaning decoupled from the specific model (Hunyuan hy3 or another) — the same credit pool can call Hunyuan, DeepSeek, or other models WorkBuddy plugs in. A reasonable design point (no single-model lock-in).
  5. The current round (Round 5) ends when this round ends; next round's rules may tweak. Key point: the "Round 5 ends 7/29" in the screenshot is a window only one day away, deciding whether to board now.

Author's notes

  • It's not a "cost-free perpetual motion machine" — you must manually check in daily to keep credits flowing in and out balanced, unlike "turn on the tap and water flows". But since check-in takes only 30 seconds, forming the habit adds no friction.
  • The "zero = overdue" strategy ≠ harsh, quite the opposite — its benefit: you can tell from yesterday's exact balance "can I run this Agent today", instead of reading token bills in the backend.
  • Practical meaning for indie devs / small teams: today (7/28), just log in and check in, and you still have 125.7 universal credits to call Hunyuan hy3; theoretically +100 daily + tasks keeps long-term cash cost at zero.
  • Risks: ① after "Round 5 ends 7/29", Round 6 rules may change (credit multiplier, check-in reward may adjust) — don't treat today's numbers as a permanent contract; ② universal credits aren't money, can't migrate across platforms/tools, so once decoupled from WorkBuddy, these credits go to zero.

Author's practical advice

  1. Do one check-in immediately — rather than starting tasks right after registration. Even with 100 credits left, it's not enough for a meaningful complex task (one full Agent run typically deducts 30–100, needs testing(to be tested later)).
  2. Before each Agent run, check the balance first (the "Credit balance" row in the S4 screenshot), estimate whether you can afford one full call; if balance is less than 1/3 of the task budget, check in / do tasks first.
  3. Watch the green banner at top-right "Buddy Refuel Station · Round X · ends Y/M/D". After this round, next round's rules may be completely different — the source of all risk calculation.

V. Why Is "Hunyuan hy3" the Key? The Author's Take on the Model Layer

The title says "Free Agent (Hunyuan hy3)" to front-load the two words readers care about most — "free" and "which model to pick". But these two things are actually two layers in WorkBuddy:

  • WorkBuddy layer: orchestration / tool calling / result delivery / credit ledger (i.e., §IV).
  • Model layer: the actual "compute" engine — you can pick Hunyuan hy3 or another model (which ones WorkBuddy ships, and whether toggles exist, see §VI).

Why this article focuses on "Hunyuan hy3":

  1. Hunyuan is Tencent's full-stack self-developed large model; hy3 is one of its current mainstream versions — meaning smoother alignment in Chinese scenarios, Tencent office ecosystem integration, and with WorkBuddy.
  2. "Limited-time free + no usage cap" is a very aggressive strategy — the most worth-boarding window. Once the model starts billing per token, the free tier often becomes "low rate / queued" or "conditionally free" — you still hold the choice, but opportunity cost rises.
  3. For indie devs / SMBs, free = ¥0 cash = no "subscription creep" anxiety of "using it and it becomes a subscription".

Author's reminder: picking a model isn't just "see which is free", but also: ① whether the model is tool-call adapted inside WorkBuddy (not every model can mount tools); ② long-context support; ③ Chinese output stability; ④ whether it "hallucinates". Real test data for these abilities will be filled in the later "running real tasks" section.

VI. Model Selection: How to Find the Free Hy3

The first step many readers care about: "Where exactly do I pick a model in WorkBuddy? Can I default to Hunyuan?" — this section nails it with one real screenshot.

6.1 Entry & default

  • Entry: bottom-right of WorkBuddy's main UI, the Hy3 ^ button at the lower-left of the input box (S5 red-box position). Click to open the model dropdown.
  • Current default: the dropdown top has two toggle layers (Max mode / Auto), Auto on by default; directly under Auto is Hy3 · Limited-time free · 0.00x with a green check ✓ on the right — meaning after the author logs in, Hy3 is the default running model, no extra click needed.
  • So for zero-threshold users: open app → New Task → input → run, and the model is Hy3.

6.2 Hy3's key markers

  • Blue circular Hy3 logo.
  • Red "Limited-time free" badge — strongly echoes the "Round 5 ends 7/29" from §IV: the badge is both strong evidence of free and a note that the free period has a time window.
  • Price multiplier 0.00x — not a discount, truly "zero multiplier"; other models are all > 0 (e.g., GLM-5.2 0.79x, GLM-5.1 0.79x, GLM-5v-Turbo 0.95x, MiniMax-M3 0.25x, Kimi-K3 1.62x, Kimi-K2.7-Code 0.57x…), meaning Hy3 is genuinely the unbilled tier. Especially friendly for long tasks — other models' token multiplier × time length easily eats dozens of credits, while Hy3 is ¥0 cash + 0 credit multiplier.

6.4 The model picker's other two toggles (pinned at top)

  • Max mode (top toggle): enabling calls a stronger reasoning mode, longer latency, and more credit consumption (Hy3 stays ¥0 cash, but the credit multiplier changes (to be tested later)).
  • Auto (Auto toggle): Auto = WorkBuddy's router decides the model; manual select = you lock the model. Each fits a scenario —
    • Pick Auto: let the platform "pick the tool", good for "vague task description, I want to see how the Agent does it first" exploration.
    • Pick Hy3 (uncheck Auto): lock Hy3, save money, controllable results.
  • At the bottom there's also a row Configure custom models, meaning WorkBuddy supports adding your own custom models (e.g., local Ollama or self-hosted) — critical for enterprises with privatization needs, meaning WorkBuddy isn't a closed product that "only runs cloud SaaS models".

6.5 Other UI elements (noted for later sections)

  • Working / Coding / Design: three "Agent mode" switches — WorkBuddy's tiers for Agent personality/workflow, deciding the tool set and system prompt called. The same model behaves differently across modes.
  • Input-box hint: "What can I help you with today? @ to reference files, / to invoke skills" — meaning WorkBuddy reuses the two trigger syntaxes of mainstream Agent IDEs: @ to reference files, / to call built-in skills. Very friendly for "users switching from other AI IDEs", near-zero onboarding cost.
  • Below the input box: Select workspace (choose workspace) + Default permission — meaning each task can bind to a different workspace (= different project context), and the default permission is adjustable.
  • Top-left floating window: activity notification "Share 650 credits/person with friends" — directly corresponds to §IV's "earn credits by doing tasks" path: one of the specific plays of the "Buddy Refuel Station Round 5" event is inviting friends. Opening it should show the invite link (filled in later).
  • Top-right Growth Rewards button — jumps straight to the S4 credits page.

6.6 Author's decision

From this point on, all "author hands-on" sections (§VII §VIII §IX) default to running under Hy3, for three reasons:

  1. 0 multiplier → credit consumption is proportional to time, unrelated to tokens → easy to do real "credit consumption rate" bookkeeping.
  2. Same ecosystem as WorkBuddy → highest fit for Chinese output and office scenarios.
  3. This is the model the author's remaining 125.7 credits this round are most likely to spend — a hands-on sample close to the reader's own situation.

VIII. Conclusions We Can Draw So Far

Based on the six confirmed facts (positioning + WeChat login + download/client + New Task entry + credit system + model picker UI), we can give provisional conclusions:

  • Low registration barrier: WeChat login in one step; domestic users enter the workbench within 30 seconds.
  • Client / Web dual-track: starting with "Use online" without installing is a reasonable first step; once installed, use top-left New Task to chat / publish tasks.
  • The real meaning of "free" is nailed by screenshots: the underlying model is free for a limited time with no usage cap (this round to 2026-07-29), the account must keep credit balance > 0, otherwise defaults to overdue and disables the free model. Daily check-in grants 100 universal credits; author's current balance 125.7.
  • Hunyuan hy3 is locked as the default by the product UI: Hy3 is pinned at the top of the model list, marked "Limited-time free · 0.00x", and is the default after login — no extra click needed to use the free model. Other optional models (GLM-5.x, Kimi-K3, etc.) range from 0.25x to 1.62x — an outlet for "want it more pro" users, and a default for "just want it easy" users.
  • Work-efficiency comparison: real tests show a significant efficiency gap between using the WorkBuddy Agent vs. direct web interaction for writing articles. Taking a long review like this one as an example:
    • Direct web interaction: every time code or terminal output is generated, you must repeatedly copy-paste into the next round of conversation; on average a 15–20 minute session needs 5–8 copy-paste actions. A 3,000-character article takes ~60–90 minutes.
    • WorkBuddy Agent: one instruction auto-generates the complete content, including structured layout, embedded code blocks, and multiple iterative refinements; the same length takes ~8–15 minutes.

    Efficiency multiplier: the Agent is roughly 6–10× the web version (i.e., the web version is 1/6 to 1/10 of the Agent). The core difference: the Agent eliminates copy-paste friction, while the web version's "copy-select-paste-refresh" loop is the efficiency killer — especially obvious when writing code-analysis content.

    Caveat: the following core metrics are still untested — ① how many credits one chat task actually deducts; ② how many credits one multi-step task actually deducts; ③ Hy3's output quality and stability under multi-step tool calling. Don't claim WorkBuddy is "invincible" based on this section alone — conclusions may change once the remaining screenshots are filled in.
