Running a Free Agent on WorkBuddy (Hunyuan hy3): A Hands-on Log

By Tan Haosheng · 副主任医师 / 医学博士 (Associate Chief Physician, MD/PhD) · 甲状腺乳腺外科 (Thyroid & Breast Surgery), 泰州市人民医院 (Taizhou People's Hospital)

🔥 FEATURED 🆓 Free-tool test 🤖 AI Agent

If you have wanted to use an Agent to automate weekly reports, write scripts, or tidy up data — but kept getting stuck on two things: "it's expensive" and "I have to set up an environment" — this article is worth your time. The author, Tan Haosheng, treats Tencent's WorkBuddy (workbuddy.cn) as a "visual Agent orchestrator." It ships with a selectable Hunyuan hy3 model that is free for a limited time, with no usage cap. As long as your account's credit balance stays above zero (credits are earned by completing tasks or a daily check-in), you can keep running a $0/month Agent.

1. What is WorkBuddy? Positioning and Official Stance

Open https://workbuddy.cn, and WorkBuddy's own introduction is refreshingly direct:

WorkBuddy is Tencent's full-scenario AI office workbench. Tell it what you need, it starts executing the task and delivers the complete result. It connects seamlessly with Tencent's office ecosystem — your reliable office sidekick.

This maps to S1 — the core area of the homepage:

Three signals jump out from this single screenshot:

  • "Full-scenario AI office workbench" — not chat-only, but a flow product of "task → execution → deliverable," which fits mainstream office scenarios well.
  • "Connects with Tencent's office ecosystem" — meaning it can integrate directly with WeChat, WeCom (Enterprise WeChat), Tencent Docs, and ecosystem tools. This is hugely important for domestic office users, removing the "export then re-import" pain.
  • "Download / Use online" side by side — the desktop client and the web version are the same product, consistent across devices. Friendly for users who want to "launch an Agent anytime, anywhere."

Author's take: Clear positioning, tightly bound to the local ecosystem — this is WorkBuddy's biggest differentiator versus overseas tools like ChatGPT and Claude. If you already work inside Tencent Docs and WeCom, the output an Agent produces can drop straight into your existing workflow instead of being shuttled across systems.

2. Registration & Login: It Starts With "WeChat"

After clicking Log in at the top-right of the homepage, a login modal appears — a large "WeChat login" button sits center, with "Phone / Email / SSO" as secondary options below.

Three facts read from this screenshot:

  1. No "GitHub / Google third-party login" — a typical account-system choice for a domestic product (phone / WeChat / email). Friendly for domestic users, but less so for overseas readers, meaning the internationalization path relies on email or SSO.
  2. A red "Please read and agree to the User Service Agreement and Privacy Policy" prompt sits at the top — a clear compliance intent, but you must tick the box before you can agree; this step cannot be skipped. One extra action for individuals, but good news for enterprise IT (easier to audit).
  3. The SSO option exists — meaning the enterprise tier can plug into its own identity system; if teams adopt it later, they can manage via a corporate account. Most individual users won't need this yet, but it's decisive for judging "can I deploy this for a team."

Author's take: "WeChat login as the only primary" has two implications:

  • ✅ Convenient: domestic users finish sign-up and login in ~3 seconds, zero friction.
  • ⚠️ Risk: the account itself is a WeChat identity weakly tied to a phone number. Long-term, avoid hanging all your core Agents/tasks on a single WeChat account — if the WeChat end gets banned/unbound (extreme case), recovery costs more than with an email account.

So the recommendation: log in with a WeChat account you control; do not borrow someone else's WeChat or use a throwaway account — the Agents, credits, and task data you produce later all travel with that identity.

3. Download & Install: Client and Web, Two Tracks

Before logging in, go back to S1 — notice the top nav's Download button and the "Download now" button in the lower half of the hero. Both entries lead to the same download page (screenshot S3).

This screenshot mainly shows three things:

  1. UI changes before/after login — top-right went from "Log in" to a user avatar icon (green), meaning login state and download state are fully connected: you can log in then download, or download then log in; either path works independently.
  2. "Download now" and "Use online" coexist — meaning WorkBuddy does not force a client install. For users who just want to "try it once," clicking "Use online" with zero install is the better starting point (avoids system-compatibility issues).
  3. Two redundant download entries (top "Download" + in-page "Download now") — a common product convention that minimizes the decision path.

Author's hands-on: first step after login

After logging in on macOS, WorkBuddy's main interface has a "New Task" button at the top-left. Clicking it opens a task input box — you can either type a normal chat command for a single Agent reply (like ChatGPT's chat-once mode), or publish a full task, letting the Agent call tools in the background and deliver a usable result. This is a product-level simplification:

  • Chat = single-turn interaction; type and see the result immediately;
  • Publish task = drop the task into the Agent's "workflow"; it breaks the steps itself, calls tools, produces files, and delivers them to the task for you.

The key difference: chat consumes fewer credits but only answers once; publishing a task consumes more credits but runs multi-step and auto-delivers artifacts. The exact credit consumption rate (to be measured) will be tested once the author actually finishes a task.

Concrete flow: Log into the app → top-left New Task → type the task description → press Enter for chat / press the "Publish" button for a full task. Section 6 below demonstrates both usages.

Core mechanism (author's summary)

  1. "Free" means the underlying model (Hunyuan hy3) is free for a limited time, with no usage cap — not billed per token, no cap on call count.
  2. The user must keep the account "credit balance > 0." Balance hits zero → account defaults to overdue status → calling the free model is immediately cut off.
  3. Credits are earned two ways:
    • (A) Complete tasks: WorkBuddy's built-in "earn credits" task list (exact rewards vary by current page, since events change per round — this must be checked precisely in-app under "Growth Plan / Task Center" (author will screenshot the Task Center later)).
    • (B) Daily check-in: a fixed 100 universal credits / day this round (confirmed by S4), claim with one mindless click; consecutive check-ins add merch rewards.
  4. Credits are "universal credits", meaning decoupled from any specific model (Hunyuan hy3 or another) — the same credit pool can call Hunyuan, DeepSeek, or other models WorkBuddy has integrated. A sensible design point (not locked to a single model).
  5. The current round (Round 5) ends with this round; next round's credit rules may shift slightly. Key point: the "Round 5 ends 7/29" in the screenshot is a window only ~1 day away, deciding whether to get on board now.

Author's take

  • It's not a "cost-free perpetual motion machine" — you must manually check in daily to keep credits flowing in and out balanced, unlike "turn on the tap and water comes." But since check-in takes only 30 seconds, forming the habit adds no friction.
  • The "zero balance = overdue" policy ≠ harsh, quite the opposite — its benefit: you can judge "can I run this Agent today" from the previous day's specific balance number, instead of reading a backend bill to count tokens.
  • Practical meaning for indie devs / small teams: Today (7/28), just log in and check in, and you still have 125.7 universal credits to call Hunyuan hy3; theoretically +100 daily from check-in + tasks keeps it at $0 cash outlay long-term.
  • Risks: ① After "Round 5 ends 7/29", Round 6's rules may change (credit multiplier, check-in reward may both be adjusted) — do not treat today's numbers as a permanent contract; ② universal credits are not money — they cannot migrate across platforms/tools, so once you leave WorkBuddy, these credits go to zero.

Author's hands-on advice

  1. Do a check-in immediately — rather than starting tasks right after sign-up. Even with 100 credits left, it's not enough for a meaningful complex task (a full Agent run usually costs ~30–100, needs measurement (to be measured)).
  2. Before each Agent run, check the balance first (the "Credit balance" row in the S4 screenshot), estimate whether you can absorb one full call; if balance is below 1/3 of the task budget, check in / do tasks first.
  3. Watch the green banner top-right "Buddy Gas Station · Round X · ends Y/M/D." After this round ends, next round's rules may be completely different — this is the source of all risk calculations.

5. Why "Hunyuan hy3" Is the Key? The Author's Read on the Model Layer

The title says "run a free Agent (Hunyuan hy3)" to front-load the two words readers care about most — "free" and "which model to pick." But these are actually two layers inside WorkBuddy:

  • WorkBuddy layer: orchestration / tool calls / result delivery / credit ledger (what Section 4 covers).
  • Model layer: the actual "computing" engine — you can pick Hunyuan hy3, or other models (which ones WorkBuddy has built in, and whether a toggle is needed, see Section 6).

Why this article focuses on "Hunyuan hy3":

  1. Hunyuan is Tencent's full-stack self-developed model; hy3 is one of its current mainstream versions — meaning smoother alignment in Chinese scenarios, connecting to Tencent's office ecosystem, and with WorkBuddy itself.
  2. "Free for a limited time + no usage cap" is a very aggressive strategy — the most worth-getting-on-board window. Once a model starts billing per token, the free tier often becomes "low rate / queued" or "conditionally free" — the choice is still yours, but the opportunity cost is growing.
  3. For indie devs / SMBs, free = $0 cash = no "it slowly turned into a subscription" anxiety.

Author's reminder: picking a model isn't just "see which is free" — also check: ① whether the model is tool-call adapted inside WorkBuddy (not all models can mount tools); ② long-context support; ③ Chinese-expression stability; ④ whether it "hallucinates output." Measured data for these will be filled in the later "running real tasks" section.

6. Model Selection: How to Find the Free Hy3

What many readers care about first is: "Where exactly do I pick a model in WorkBuddy? Can I default to Hunyuan?" — this section nails it down with one real screenshot.

6.1 Entry and default

  • Entry: bottom-right of WorkBuddy's main UI, the Hy3 ^ button at the lower-left of the input box (the red-rectangle position in S5). Click to open the model dropdown.
  • Current default selection: the top of the dropdown has two toggle layers (Max mode / Auto); Auto is ON by default; right below Auto is Hy3 · Limited-time free · 0.00x, with a green check ✓ on the right — meaning the author's default after login is already Hy3 running, no extra click needed.
  • So for zero-threshold users: open app → click New Task → type → run, and the model is Hy3.

6.2 Hy3's key identifiers

  • Blue circular Hy3 logo.
  • Red "Limited-time free" badge — strongly echoes the "Round 5 ends 7/29" from Section 4: the badge is strong evidence of free, yet points out the free offer has a time window.
  • Price multiplier 0.00x — not a discount, but a true "zero multiplier"; all other models are > 0 (e.g., GLM-5.2 0.79x, GLM-5.1 0.79x, GLM-5v-Turbo 0.95x, MiniMax-M3 0.25x, Kimi-K3 1.62x, Kimi-K2.7-Code 0.57x…), meaning Hy3 is genuinely the unbilled tier. This is especially friendly for long tasks — other models' token multiplier × duration easily eats dozens of credits, while Hy3 is $0 cash + 0 credit multiplier.

6.4 The other two toggles in the model-picker dialog (pinned)

  • Max mode (top toggle): turns on a stronger reasoning mode; runtime lengthens and credit consumption rises (Hy3 is still $0 cash, but the credit multiplier changes (to be measured)).
  • Auto (Auto toggle): Auto = WorkBuddy routes the model; manual pick = you lock the model. Each fits a scenario —
    • Pick Auto: let the platform "pick the tool" — good for "vague task description, I want to see how the Agent does it first" exploration.
    • Pick Hy3 (uncheck Auto): lock Hy3, save money, controllable results.
  • At the bottom there's also a line Configure custom models, meaning WorkBuddy lets you add your own custom models (e.g., local Ollama or self-hosted) — critical for enterprise users with privatization needs, meaning WorkBuddy is not a closed product that "can only run cloud SaaS models."

6.5 Other UI elements (noted for later sections)

  • Working / Coding / Design: three "Agent mode" switches — WorkBuddy's tiers for Agent personality/workflow, deciding which tool set and system prompt are called. The same model behaves differently across modes.
  • Input-box placeholder: "What can I help you with today? @ to reference files, / to invoke skills" — meaning WorkBuddy reuses the two trigger syntaxes of mainstream Agent IDEs: @ references files, / calls built-in skills. Very friendly for "users switching from other AI IDEs," near-zero onboarding cost.
  • Below the input box: Select workspace + Default permission — meaning each task can bind to a different workspace (= different project context), and the default permission is adjustable.
  • Top-left floating window: activity notice "Share with friends: 650 credits/person" — this directly corresponds to the "earn credits by tasks" path in Section 4: one of the specific plays of the "Buddy Gas Station Round 5" event is inviting friends. Clicking should reveal an invite link (to be filled in later).
  • Top-right Growth Rewards button — jumps straight to the S4 credits page.

6.6 Author's decision

From here on, all "author hands-on" sections (§7 §8 §9) default to running under Hy3, for three reasons:

  1. 0 multiplier → credit consumption is proportional to time, unrelated to tokens → easy to do real "credit consumption rate" accounting.
  2. Same ecosystem as WorkBuddy → highest fit for Chinese output and office scenarios.
  3. This is the model the author's remaining 125.7 credits this round are most likely to spend on — giving readers a hands-on sample close to their own.

8. Conclusions So Far

Based on the six confirmed sections of fact (positioning + WeChat login + download/client + New Task entry + credits system + model-picker UI), here is a stage conclusion:

  • Low registration barrier: WeChat login in one step; domestic users enter the workbench within 30 seconds.
  • Client / Web, two tracks: starting with "Use online" without installing is a reasonable path; once installed, use top-left New Task to trigger chat / publish task.
  • The real meaning of "free" is nailed by screenshots: the underlying model is free for a limited time + no usage cap (this round until 2026-07-29); the account must keep credit balance > 0, otherwise defaults to overdue and disables the free model. Daily check-in grants 100 universal credits; the author's current balance is 125.7.
  • Hunyuan hy3 is already locked as the product UI default: Hy3 is pinned at the top of the model list with a "Limited-time free · 0.00x" badge; after login the default is already Hy3, no extra click needed to use the free model. Other optional models (GLM-5.x, Kimi-K3, etc.) range from 0.25x to 1.62x — an exit for "want to run more professionally," and a default for "just want it easy."

Caveat: The following core metrics are still untested — ① how many credits a single chat task actually deducts; ② how many credits a single multi-step task actually deducts; ③ Hy3's output quality and stability under multi-step tool calls. Do not claim WorkBuddy is "invincible" based on this section alone — the conclusion may change once the remaining screenshots are filled in.
