2 a.m., the build is red

The CI failed at 2:04 a.m. Three engineers crowd one monitor. The question on the screen: do we rewrite the dashboard in React, or ship the vanilla version that already works? None of them disagree that JavaScript is the language. They disagree about everything built on top of it. Pull up a chair. Three personas, one language.

The players

  • The Framework Maximalist — ships React/Next, lives in components, trusts the ecosystem.
  • The Vanilla Purist — web standards only, zero runtime deps, reads the spec.
  • The TypeScript Pragmatist — picks the smallest tool that removes a class of bug, usually TS plus one framework.

Round 1 — the language itself

Purist: "The language is enough. Look at what landed without a framework."

// ES2023: Array.fromAsync, Object.hasOwn
const users = await Array.fromAsync(userStream);
if (Object.hasOwn(config, "theme")) applyTheme(config.theme);

// ES2024: Object.groupBy
const byRole = Object.groupBy(members, m => m.role);

Maximalist: "Cute. Now render 200 rows that update on keystroke without a framework and tell me your code is shorter."

Pragmatist: "Both miss the point. The spec sheet that matters is what's shipped and supported. Optional chaining (?.) and nullish coalescing (??) — ES2020 — removed more null-crash bugs than any framework. That's the real essential." Source: tc39.es proposal stages.

Round 2 — the cost of a dependency

Pragmatist: "Here's the pricing math nobody quotes. React 18 + react-dom is ~45KB gzipped (widely cited baseline). A misconfigured build that pulls a full lodash ships 70KB+ for five functions. Vanilla: 0KB runtime."

// pay only for what you use
import debounce from "lodash/debounce"; // ~2KB, not all of lodash

Maximalist: "45KB buys you a renderer, state, and a hiring pool. Try hiring a 'vanilla DOM' engineer in 2026."

Purist: "Try debugging a 400KB bundle at 2 a.m. The cost isn't bytes. It's the surface area you don't control."

Round 3 — async, the part everyone gets wrong

Pragmatist: "Promise, async/await (ES2017), and the event loop. Master these and 80% of production bugs disappear." Real scenario: the dashboard fires 50 requests on mount.

// wrong: 50 parallel, unbatched
// right: bounded concurrency
async function run(tasks, limit = 5) {
  const out = [];
  while (tasks.length) out.push(...await Promise.all(tasks.splice(0, limit).map(t => t())));
  return out;
}

Purist: "Native, no dep. That's the whole argument."

Maximalist: "And in React it's a useEffect with an abort controller. Same logic, better colocation."

Where they actually agree

  • ES modules (import/export) beat globals — non-negotiable since ~2018.
  • TypeScript catches an entire bug class; even the Purist concedes tsc --noEmit on a build step.
  • The DOM and Fetch API are the stable floor; frameworks come and go.

Choosing by your situation

  • Static page, small team, long life: vanilla + a build step. Zero runtime risk.
  • Interactive app, hiring for scale: a framework (React/Vue/Svelte) + TypeScript.
  • Anything with money on the line: TypeScript, full stop.

Frequently asked questions

Do I need a framework to learn JS?

No. Learn the language — modules, promises, the DOM, Fetch — first. A framework is a layer on top; without the base it's cargo-culting. The Purist's position, and the right starting point.

Is TypeScript worth the setup?

For anything beyond a toy, yes. It catches null/type bugs at compile time that would otherwise reach production. The Pragmatist's non-negotiable.

Which framework should I pick?

React (largest ecosystem/hiring), Vue (gentle curve), Svelte (small output). The Maximalist picks React for the talent pool; the Purist would skip all three. Match the framework to your team, not a leaderboard.

Are new JS features safe to use?

Once they reach ECMAScript standard and your targets support them (check caniuse/MDN), yes. Stage-2 proposals are not safe for production. Verify support on developer.mozilla.org.

Verdict: JavaScript essentials are the language, not the framework. Learn modules, promises, the DOM, and Fetch cold; add TypeScript the moment code matters; reach for a framework only when the app's interactivity outgrows hand-rolled state. The honest caveat: none of the three personas is right in the abstract — the Vanilla Purist ships faster on small surfaces, the Maximalist scales a team, the Pragmatist minimizes regret. Pick the voice that matches your risk, not the loudest one at 2 a.m.
