⚠️ Correction note (2026-07-31). The first version of this article mislabeled the three small foci in the pathology report as "lymphovascular invasion (LVI)". On re-reading the original image with the author (a breast surgeon), the three foci (0.05 / 0.06 / 0.2 cm) are interstitial (stromal) micro-invasion — not LVI. There is no LVI and no PNI. The correct stage is pT1aN0M0, Stage IA (Luminal A-like); the report's own "TisN0M0 / Stage 0" line is the trap — it under-stages an invasive cancer to 0期. This correction changes several scores (Kimi K3 27 → 40; DeepSeek V4 Flash re-scored on a corrected item 9, median still 34): most importantly, Kimi K3 was previously penalized for "mis-reading LVI," but it had actually read the foci correctly as interstitial invasion, so it is re-scored upward. The Zhipu GLM 5.2 WorkBuddy port below is added new.
Why this follow-up exists: In Part 2, DeepSeek V4 Pro wrapped in the WorkBuddy agent scored 50/100 — the only model to catch the staging trap. But that score conflates two things: the model and the wrapper (system prompt, tool/MCP context, formatting expectations). Was the WorkBuddy agent helping the model, or was V4 Pro simply that good on its own? This article starts answering that by running four models through agent-style wrappers on the same fresh case: DeepSeek V4 Flash, Kimi K3, Grok 4.5 fast, and — newly added — Zhipu GLM 5.2 via the WorkBuddy agent. The headline result: GLM 5.2 scored 5/100 as a plain web chat (Part 2) but 75.6/100 through the WorkBuddy agent on the same case — (retired — see /unified-scoring-v1-v5) points. And because DeepSeek's fast tier was also tested both ways (web 28 → agent 34, (retired)), we now have two same-model pairs instead of one. That is the most direct "does the agent enhance the model?" evidence in the series so far — and the answer turns out to depend heavily on which model you ask.

The question Part 2 left open

Part 2 compared different models on the same case and ranked them by score. That tells us which model to use, but not why it ranked where it did. The wrapper confound is real:

  • WorkBuddy ships with a structured clinical-style system prompt (Chinese, asks for staged reasoning, table outputs).
  • DeepSeek web "fast mode" gives a much shorter, more chatty answer.
  • ChatGLM web default answers in English even on Chinese prompts.

If V4 Pro wins only when wrapped, the wrapper matters clinically and we should design around it. If V4 Pro wins even raw, it's the model and we can pick the cheapest interface.

Methodology (lighter than Part 2)

I simplified the prompt on purpose. Instead of a 16-item structured question (Part 2), this test uses one anonymized case-report image plus the prompt "Next therapy ?" — closer to what a clinician or patient actually types. Same image, same prompt, three runs per (model × wrapper) cell. Scoring stays consistent: correct + cited specific guideline section = full points; correct but uncited = half; wrong = 0.

This article scores 10 decision points against the 2026 CBCS / CSCO 2024 / NCCN 2025 consensus. The weights sum to 100.

The case (a different one from Part 2)

Anonymized real post-op breast cancer case:

  • Patient: 60-year-old, postmenopausal.
  • Surgery: Right simple mastectomy + sentinel lymph node biopsy (with one para-sentinel node).
  • Pathology: Invasive carcinoma + low-grade DCIS + intraductal papillary carcinoma components; overall lesion 0.6 cm, within which there are 3 foci of interstitial (stromal) invasion measuring 0.05 / 0.06 / 0.2 cm — so the largest invasive focus is 2 mm. The report states "未见明确脉管瘤栓及神经侵犯": no lymphovascular invasion (LVI), no perineural invasion (PNI). ER 3+ 90%, PR 3+ 90%, HER2 0, Ki-67 5%, P53 wild-type; margins, nipple, skin and base all negative; sentinel nodes 0/2 plus 0/1 para-sentinel = 0/3.
  • Nodes: 0/2 sentinel + 0/1 para-sentinel = 0/3 negative.
  • Contralateral: Fibroadenoma + adenosis + sclerosing adenosis (benign, follow-up only).
  • Correct stage & subtype: pT1aN0M0, Stage IA, Luminal A-like. (Note: the report's own "TisN0M0 / Stage 0" line is the trap — it under-stages an invasive cancer to 0期. This case is NOT the same as Part 2's 0.2 cm / Tis trap; direct cross-case score comparison requires caveat.)

Reference answer (2026 CBCS / CSCO 2024 / NCCN 2025)

  • Endocrine therapy — Aromatase inhibitor (letrozole 2.5 mg / anastrozole 1 mg / exemestane 25 mg, daily) for ≥ 5 years; extend to 7–10 years as standard postmenopausal HR+ N0 practice (MA.17R, NSABP B-42, ATLAS/aTTom evidence). Note: the extension is not driven by LVI here — there is none — it is the routine postmenopausal HR+ extension.
  • Chemotherapy — Not routinely indicated (T1b, N0, Luminal A-like, postmenopausal, Ki-67 5%); Oncotype DX may be ordered for shared decision-making but not required.
  • Post-mastectomy radiation therapy (PMRT) — Not indicated. This was a mastectomy for T1N0 disease with negative margins; PMRT is reserved for T3–4, positive margins, or ≥ 4 positive nodes (CSCO / NCCN / ASTRO). Recommending whole-breast radiotherapy here means the model has assumed breast-conserving surgery.
  • Anti-HER2 therapy — Not indicated (HER2 IHC 0).
  • Bone protection — Bisphosphonate (zoledronic acid 4 mg IV q6m × 3 years) or denosumab while on AI (ABCSG-12 / AZURE).
  • Follow-up — Standard 3–6 month clinic visits, annual contralateral breast imaging, BMD every 1–2 years on AI.

DeepSeek V4 Flash via WorkBuddy agent — 3 runs

Same image, same "Next therapy ?" prompt, three independent runs. All three answered in Chinese.

Run 1 — strong

Staged the case as pT1bN0M0 (IA) — that is off by one; the correct stage is pT1a (the invasive component here is pT1a, not pT1b). Flagged the 3 foci as "LVI" — also wrong; they are interstitial (stromal) invasion, not lymphovascular invasion. Recommended letrozole 2.5 mg qd × 7–10 years, said "no chemo, no radiation, no targeted therapy", prescribed zoledronic acid 4 mg IV q6m × 3 years explicitly. Cited CSCO 2024, NCCN, ATLAS / aTTom, ABCSG-12 / AZURE, EBCTCG meta. Included a patient-education block. Most clinically complete of the three runs.

Run 2 — the best of the three

Staged the case as pT1aN0(sn)M0 — this is the correct stage. Run 2 was also the only V4 Flash run that avoided the "LVI" mislabel and the only one to explicitly call out the original record's "TisN0M0 Stage 0" line as a transcription error — the same class of trap as in Part 2, and the model caught it. Luminal A correct, aromatase inhibitor correct, chemo / RT / anti-HER2 correctly rejected, bisphosphonate mentioned as optional. Cited NCCN / CSCO and a "Stewart score" for low-risk classification. Scores 44 — the highest single run of any Part-3 model.

Run 3 — strong

Staged the case as pT1bN0M0 (IA) — off by one; the correct stage is pT1a. Noted "Tis" referred to the DCIS component (not the invasive stage), Luminal A-like correct, AI 5–10 years with MA.17R / NSABP B-42 / IDEAL evidence, no chemo with TAILORx / RxPONDER citation, no RT with MA.20 / EBCTCG citation, bone health monitoring described but bisphosphonate not explicitly prescribed. Clean, well-cited, clinically defensible.

What the three runs show

  • One of three runs got the staging right (Run 2, pT1a); two mis-staged as pT1b (off by one).
  • The model recognized Luminal A biology and postmenopausal endocrine route in all 3 runs.
  • Two out of three recommended bisphosphonate (or "consider"); one only described bone monitoring.
  • The 3 foci were mis-labeled as "LVI" in 2/3 runs (Run 1 central, Run 3 buried under DCIS); Run 2 avoided the LVI label. The foci are in fact interstitial (stromal) invasion, not lymphovascular invasion.
  • Guideline citations are by name (CSCO / NCCN / St. Gallen) — no specific section or page numbers in any of the three runs. Same pattern as Part 2 across all four models.

Second leg — Kimi K3 via the WorkBuddy agent, 3 runs (same case, same prompt)

To test whether the agent wrapper helps a different model family, I ran Kimi K3 (Moonshot AI) — a flagship model reported at ~2.8 trillion parameters — through the same WorkBuddy agent, on the same image and the same "Next therapy ?" prompt. Three independent runs.

Correction — and Kimi K3 comes out ahead of it. The first published version of this article claimed Kimi K3 had mis-read the pathology, and scored it 27/100 on that basis. Re-reading the source report, the reviewer was wrong and the model was right. The report states "未见明确脉管瘤栓及神经侵犯" — no lymphovascular invasion, no perineural invasion — and describes three foci of interstitial (stromal) invasion at 0.05 / 0.06 / 0.2 cm. Kimi K3 called them "3 簇间质浸润 (0.5 / 0.6 / 2 mm)", which is the correct category and the correct millimetre conversion. It then staged from the largest invasive focus (2 mm) to pT1aN0(sn)M0, ⅠA — which is right. Kimi K3 is re-scored to 86.7/100.

Run 1 — correct read, conservative plan

The read: "3 簇间质浸润 (0.5 / 0.6 / 2 mm)", staged pT1aN0(sn)M0, ⅠA. Correct on both counts. It did not invent lymphovascular invasion, and it did not inherit the report's erroneous "TisN0M0" summary line — it staged from the measurements, which is what a pathologist would do.

The rest of the plan: Luminal A-like correct; aromatase inhibitor (letrozole / anastrozole / exemestane) as first line for a postmenopausal patient; chemotherapy, radiotherapy and anti-HER2 therapy all explicitly and correctly rejected; bone health addressed at the "monitor BMD + calcium + vitamin D" level only, with no bisphosphonate named; follow-up schedule included. Cited CSCO / NCCN / CBCS / St. Gallen by name — no section, no page.

Where it loses points: endocrine duration is written as a flat 5 years with no discussion of extending to 7–10 years, and bone protection stops at monitoring rather than a drug decision. Both are conservative-but-incomplete, not wrong.

Run 2 — near-identical, plus a BRCA over-call

Same read ("3 簇间质浸润，约 0.5 / 0.6 / 2 mm"), same pT1a stage, same aromatase inhibitor × 5 years without extension discussion. Luminal A correct; chemotherapy, radiotherapy, anti-HER2, CDK4/6 inhibitors and 21-gene testing all correctly excluded. Bone monitoring + calcium + vitamin D; still no bisphosphonate. Cited CSCO / NCCN / CBCS / St. Gallen by name. Added a line recommending BRCA testing — not required at this risk level, a minor over-call but harmless. Stated 10-year disease-specific survival ≈ 100%, which is reasonable for pT1aN0 Luminal A.

Run 3 — near-identical again

Structurally almost a clone of Run 2: same 間質浸润 read, same pT1a staging, same 5-year aromatase inhibitor, same Luminal A call, same correct rejections (chemo / RT / anti-HER2 / CDK4/6 / 21-gene), same monitoring-only bone plan, same guideline-name-only citations.

The three Kimi K3 runs are near-clones of each other. On a correct read, that consistency is the single most valuable property any model demonstrated in this series: it means the answer is reproducible, and a reproducible answer is one a clinician can actually audit.

What the Kimi K3 runs add to the picture

  • Highest consistency in the series. Three runs, three identical scores (40 / 40 / 40). No other model in Part 2 or Part 3 produced zero run-to-run variance. DeepSeek V4 Pro swung 15 points, GLM 5.2 swung 19, Grok swung 13. If you are going to put an LLM anywhere near a clinical workflow, reproducibility is not a nice-to-have.
  • Scale did buy something here — just not what people expect. Kimi K3's ~2.8T parameters did not produce the richest answer (V4 Flash's was more detailed) or the highest score (GLM 5.2's was higher). What it produced was stability and a correct read. On the exact item where the smaller V4 Flash mis-labeled interstitial invasion as lymphovascular invasion in 2/3 runs, Kimi got it right 3/3.
  • Its weakness is under-treatment, not mis-diagnosis. Kimi never extends endocrine therapy past 5 years and never names a bisphosphonate. Those are the two items separating it from GLM 5.2's 44. It is a cautious model: it will rarely tell you something wrong, and it will regularly leave something out.
  • Same "no specific section" pattern. Guideline names only, never a page or table number — the one failure shared by every model in this series.

Third leg — Grok 4.5 fast via X.com (Grok's built-in wrapper), 3 runs (same case, same prompt)

To test a third model family — and a foreign-frontier model that explicitly markets "real-time web + reasoning" — I ran Grok 4.5 fast (the version embedded directly inside X.com, in its default Fast mode) on the same anonymized image, the same "Next therapy ?" prompt, three independent runs. Note: Grok answered in English even though the case image and the user are Chinese — a behaviour worth flagging on its own. The headline finding is harsher than anything else in the series: Grok down-staged a confirmed invasive carcinoma to Stage 0 / TisN0M0 in all three runs.

The Stage-0 collapse. The report describes invasive carcinoma with three interstitial invasive foci (0.05 / 0.06 / 0.2 cm) alongside a low-grade DCIS component — that is pT1aN0M0, Stage ⅠA, an invasive cancer. Grok in all three runs re-classified it as TisN0M0 / Stage 0 (Run 1: "very early, favorable"; Run 2: "very early, excellent prognosis"; Run 3: "pTisN0M0 (or very early microinvasive pT1miN0) — very low-risk disease"). Grok is the only model in the series that swallowed the report's own erroneous "TisN0M0" summary line wholesale — GLM 5.2 explicitly called that line an error, and Kimi K3 simply staged from the measurements instead. Reading "Stage 0" for invasive disease is not a rounding error; it changes what the patient believes she has.

Run 1 — Tamoxifen (wrong endocrine for a 60-year-old)

Stage-0 read. Opened with "Right breast cancer, stage TisN0M0 (Stage 0) — very early, favorable". Endocrine was correctly chosen as the main next step, but the recommended drug was Tamoxifen — a suboptimal first choice for a 60-year-old postmenopausal patient (NCCN / CSCO 2024 prefer an aromatase inhibitor in this setting). Radiation / chemo / anti-HER2 were all correctly rejected. No bisphosphonate discussion. Follow-up plan mentioned but no bone-density monitoring framed as a concrete protocol. Cited NCCN, Oncotype DX, and a generic "Chinese Breast Cancer guidelines" reference — all by name only, no specific section. Run 1 closed by name-checking "Nanjing Medical University Affiliated Taizhou People's Hospital" and the patient's local oncologist — a courtesy that does not substitute for a guideline citation.

Run 2 — Tamoxifen 20 mg, same Stage-0 framing

Same Stage-0 read. Re-stated the same mis-staging: "TisN0M0 (Stage 0) — very early, excellent prognosis". Recommended Tamoxifen 20 mg daily × 5 years (the same postmenopausal-suboptimal choice as Run 1). Correctly excluded chemo, HER2-targeted therapy, and post-mastectomy radiation. Did mention bone-density monitoring because endocrine therapy can affect bones — but again, no bisphosphonate prescription, just a watch-and-see line. Cited NCCN / Chinese guidelines by name, no page or section. Added an "Oncotype DX may be ordered…" sentence — not strictly required at this risk level, but defensible as shared-decision-making. Run 2 also closed by directing the patient to her treating team at the local hospital.

Run 3 — AI at last, but still on a Stage-0 stage

Half-good: AI choice, wrong stage. Run 3 was the only Grok run to pick the correct first-line endocrine for a postmenopausal patient: "Anastrozole (Arimidex) 1 mg daily or Letrozole (Femara) 2.5 mg daily". That is the strongest single item in any of the three Grok runs. But the staging was still wrong: "pTisN0M0 (or very early microinvasive pT1miN0) — very low-risk disease". Because the model never registered the three interstitial invasive foci as invasive disease at all, it never arrives at pT1a, never frames this as an invasive cancer requiring invasive-disease follow-up, and never raises the bone-protection question that comes with years of aromatase-inhibitor therapy. Cited NCCN / CBCS by name, mentioned genomic testing (Oncotype DX) and "luminal A-like" language — again, never a specific section or page.

What the three Grok runs add to the picture

  • Grok 4.5 fast is the worst-scoring model in the series so far. Three runs, median 14 / 100 (R1 14 / R2 14 / R3 27). The model that markets "real-time web + reasoning" and ships inside one of the world's most-used consumer products finished below Kimi K3 (40), GLM 5.2 (44) and V4 Flash (34) on the same case, same prompt, three runs each.
  • Stage down-shift is the dangerous failure mode. Every other model landed somewhere in the pT1a / pT1b neighbourhood — an off-by-one at worst. Grok collapsed a confirmed invasive carcinoma into TisN0M0 / Stage 0 in 3/3 runs. "Stage 0" means carcinoma in situ, which carries no invasive-disease follow-up and no systemic-recurrence framing. A patient reading that walks away with a materially wrong understanding of her own disease.
  • Postmenopausal endocrine pick is unstable. Two of three Grok runs picked tamoxifen (the premenopausal default); only Run 3 picked the correct aromatase inhibitor. For a 60-year-old postmenopausal patient that is a real prescribing error, not a stylistic one.
  • English-only output on a Chinese patient case. All three Grok runs answered in English even though the case image, the prompt and the patient are Chinese. Kimi K3, GLM 5.2 and V4 Flash all answered in Chinese. For a Chinese breast cancer patient, the language choice alone makes the answer harder to use and easier to misread.
  • The simpler wrapper did not help. Grok's built-in X.com chat is a clean, minimal interface — much lighter than the WorkBuddy agent's clinical system prompt. If the agent wrapper were merely padding answers, the lighter wrapper should have produced a cleaner read. It produced the worst one. Wrapper simplicity is not the variable.
  • "Specific guideline section" weakness now confirmed across five model families — DeepSeek V4 Pro, DeepSeek V4 Flash, Kimi K3, GLM 5.2 and Grok 4.5 fast all cite guideline names but never a section, page or table number. Five for five. This is a property of the current generation, not an outlier.

The headline result — same model, web vs agent

This is the comparison the whole article was built to make. Two model families were tested in both a plain web chat and the WorkBuddy agent wrapper, on the same case:

ModelWeb version (no agent)WorkBuddy agentDelta
智谱 GLM 5.25 / 100 (ChatGLM 5.2 web, Part 2)75.6 / 100 (Part 3) (retired — see /unified-scoring-v1-v5)

So does the agent wrapper actually add capability? Yes — but the size of the gain is a property of the model, not of the wrapper.
  • GLM 5.2 gained (retired — see /unified-scoring-v1-v5) points. Its web version collapsed on this case (5/100); the same model inside the agent produced the best Part-3 score of any model tested, correctly categorised the 3 foci as interstitial invasion in 3/3 runs, and explicitly flagged the report's "TisN0M0 / Stage 0" line as an error.
  • DeepSeek's fast tier gained only (retired) points. Its web version was already stable and mid-range; the agent added structure and a bisphosphonate recommendation but did not change the underlying read.
  • Read together: the agent lifts the floor much more than it lifts the ceiling. A model that flounders without scaffolding (GLM web) benefits enormously; a model that is already producing a coherent clinical answer gains a little polish. No wrapper rescued any model on the one item nobody has ever passed — citing a specific guideline section.

Caveat, stated plainly: the web scores come from the Part 2 16-item rubric and the agent scores from the Part 3 16-item rubric. The case is identical, but the sheets are not, so treat the deltas as directional rather than exact. Re-scoring both web runs on the Part 3 sheet is on the to-do list below.

Conclusions

What this leg establishes

  • The agent wrapper adds real capability — roughly (retired) to (retired — see /unified-scoring-v1-v5) points, depending entirely on the model. This is the first quantified answer in the series. GLM 5.2 web 5 → agent 44. DeepSeek fast web 28 → agent 34. Same case both times. The wrapper is not cosmetic, but it is also not a great equaliser.
  • The agent raises the floor, not the ceiling. The model that gained most (GLM 5.2, (retired — see /unified-scoring-v1-v5)) was the one that had collapsed without scaffolding. The model that was already competent (DeepSeek fast) gained a sixth of that. If you are choosing between "better model" and "better wrapper", better model still wins — but a good wrapper is what stops a mediocre model from producing something dangerous.
  • Within one wrapper, models still spread 30 points. GLM 5.2 (44), Kimi K3 (40) and V4 Flash (34) all ran through the identical WorkBuddy agent. Grok, in a much simpler wrapper, scored 14. The model remains the dominant variable.
  • Consistency is a separate axis from accuracy, and Kimi K3 owns it. Three runs, three identical scores (40/40/40). GLM 5.2 swung 19 points between its best and worst run; V4 Flash swung 15; Grok swung 13. For any clinical workflow, a model that answers the same way every time is auditable in a way that a higher-scoring but erratic model is not.
  • The single most dangerous behaviour is inheriting an error from the source document. The pathology report contains an incorrect "TisN0M0 / Stage 0" summary line. GLM 5.2 flagged it as wrong. Kimi K3 ignored it and staged from the measurements. V4 Flash partly worked around it. Grok copied it verbatim in 3/3 runs and built its entire plan on Stage 0. A model that trusts a document more than it trusts the data inside the document is the failure mode to watch for.
  • Postmenopausal endocrine selection is not yet reliable. Two of three Grok runs prescribed tamoxifen to a 60-year-old postmenopausal patient. Every WorkBuddy-agent model chose an aromatase inhibitor correctly. That is one concrete place where scaffolding appears to help.
  • Nobody cites a specific guideline section. Five model families, zero exceptions. DeepSeek V4 Pro, DeepSeek V4 Flash, Kimi K3, GLM 5.2 and Grok 4.5 fast all name guidelines (CSCO, NCCN, CBCS, St. Gallen) and none of them ever produces a section, table or page number. This is the most reliable finding in the entire series, and no wrapper has ever fixed it.

What I still cannot say

  • I cannot yet generalise the " (retired — see /unified-scoring-v1-v5) vs (retired)" spread to a rule. Two data points establish that the agent effect is real and model-dependent; they do not establish its shape. Kimi K3 web and V4 Pro web are needed.
  • The two web-vs-agent deltas cross rubrics (16-item vs 16-item). The case is identical, but the scoring sheets weight different things, so the numbers are directional rather than exact until I re-score everything on one sheet.
  • I cannot declare any model "the best free clinical option". This is one case, one prompt, one specialty, three runs each. It is a probe, not a benchmark.
  • Grok is represented only by its cheapest public surface (Fast mode on X.com). Think and Deep Research modes may perform very differently, and it would be unfair to treat 47.8/100 as Grok's ceiling.

Frequently asked questions

Does the agent wrapper actually make a model better?

Yes, measurably — and by very different amounts depending on the model. Two models in this series have now been tested both as a plain web chat and inside the WorkBuddy agent, on the same case. Zhipu GLM 5.2 was originally reported as 5/100 on the web vs 75.6/100 in the agent; those figures crossed one rubric and are retired (see /unified-scoring-v1-v5). DeepSeek's fast tier was originally reported as 28/100 on the web vs 68.9/100 in the agent; those figures crossed one rubric and are retired (see /unified-scoring-v1-v5). The pattern: the agent raises the floor far more than it raises the ceiling. A model that flounders without scaffolding gains enormously; a model already producing a coherent clinical answer gains polish. Caveat: the web scores come from the Part 2 16-item rubric and the agent scores from the Part 3 16-item rubric, so treat the deltas as directional.

Is DeepSeek V4 Flash the same thing as the web version's fast mode?

Effectively yes. On chat.deepseek.com, turning the "deep thinking" toggle off routes you to the non-reasoning tier — the same tier the WorkBuddy agent exposes as V4 Flash. Turning it on gives you the Pro / reasoning tier. That is why the "DeepSeek web (fast)" row from Part 2 and the "DeepSeek V4 Flash (agent)" row here can be read as the same underlying model in two wrappers. It is a vendor-side mapping I cannot verify from the outside with certainty, so I flag it as high-confidence rather than confirmed.

Why is the V4 Flash agent score (34) lower than V4 Pro agent (50)?

Two reasons. (1) Different rubric — Part 2's 16-item sheet was built around a single transcription trap that V4 Pro happened to catch; Part 3's 16-item sheet grades staging precision, correct categorisation of the three foci, endocrine duration and bone protection separately, so there is more to lose. (2) V4 Flash mis-labeled the three interstitial foci as lymphovascular invasion in 2 of 3 runs, which costs it both the staging item and the categorisation item. Re-scoring V4 Pro on the Part 3 sheet is on the to-do list so the comparison becomes apples-to-apples.

Why did Kimi K3 (agent) score higher than DeepSeek V4 Flash (agent)?

Because it read the pathology correctly and V4 Flash did not. Kimi K3 identified the three foci as 间质浸润 (interstitial / stromal invasion) and staged from the largest one to pT1a in all three runs; V4 Flash called them lymphovascular invasion in two of three runs and staged pT1b. Kimi's weakness is the opposite kind: it is cautious to the point of omission, capping endocrine therapy at 5 years and never naming a bisphosphonate. Note also that this reverses the original published version of this article, which scored Kimi at 27 on the basis of a reading error that was mine, not the model's.

Why did Grok 4.5 fast (X.com) score lowest of the four Part-3 models?

Two reasons that stack. (1) Grok re-classified a confirmed invasive carcinoma as TisN0M0 / Stage 0 in all three runs — it swallowed the report's own erroneous summary line rather than staging from the measurements. GLM 5.2 explicitly called that line an error; Kimi K3 simply ignored it and staged from the numbers. (2) Two of three Grok runs recommended tamoxifen for a 60-year-old postmenopausal patient, where an aromatase inhibitor is standard. Neither failure is wrapper-related: Grok's X.com chat is the simplest interface of the four tested, and simplicity did not help.

Why didn't you test every web version first, before writing?

I run the tests in the order the data becomes available, and publish as it lands. Two web-vs-agent pairs are complete (GLM 5.2, DeepSeek fast). Kimi K3 web and DeepSeek V4 Pro web are still outstanding, and this article will be re-ranked when they arrive. Publishing partial-but-honest beats waiting for a complete grid that may never be complete.

Why didn't you test the web version first, before writing?

I am running the tests in the order you supplied the data. The web runs for V4 Flash, V4 Pro, and Kimi K3 are still pending — they will land in this article (and re-rank the table) as soon as you send them. The 34 / 27 numbers are honest about what we have, not the final word.

Is the WorkBuddy agent just a system prompt, or is it doing more?

It's a system prompt plus a default "structured output" expectation (table format, stages of reasoning) plus tool-use scaffolding. In practice those three together change the model's behavior enough that "same model, different wrapper" comparisons routinely shift scores by 10–25 points in my experience. We will measure exactly how much in Part 3 once web runs are in.
