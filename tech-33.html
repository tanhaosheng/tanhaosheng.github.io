Monday, 9 a.m., empty file

You open a blank index.html. The cursor blinks. Nothing else. The instinct is to go shopping for tools — a framework, a builder, a "platform." Stop. The cheapest parts of a website are the languages. The expensive parts are the recurring bills you didn't model. Here is the spreadsheet, written as prose.

A purely static site — HTML, CSS, a little JS — can therefore run for about $10 a year: one domain, everything else free. A dynamic app on a small VPS adds ~$5/mo, or ~$60/yr, plus the domain. That is the real floor. The marketing "free website builder" usually trades that $10 for a locked-in subdomain and a monthly upsell.

The languages are free; your time is the cost

HTML, CSS, and JavaScript cost nothing to use. The line item here is hours.

<!doctype html>
<html lang="en">
  <head><meta charset="utf-8"><title>Hello</title></head>
  <body><h1>Hello</h1></body>
</html>

That is a valid page. Everything after it is structure (HTML), presentation (CSS), and behavior (JS). Learn those three and you never pay a "builder" tax again.

HTML: the structure

HTML is a markup language, not a programming language. Tags describe meaning: <nav>, <main>, <article>, <footer>. Semantic tags are not decoration — they feed screen readers and search engines. A <div> everywhere is the most common beginner tax: it works visually and fails structurally.

CSS: the presentation

CSS controls layout and look. The two systems that matter in 2026: Flexbox for one-dimensional rows/columns, Grid for two-dimensional layouts. Responsive design rests on three mechanics — relative units (rem, %, vw), fluid images (max-width: 100%), and media queries that swap rules by viewport. Mobile-first means write the small screen first, then enhance.

JavaScript: the behavior

JS makes pages interactive. For a first site, you do not need a framework. A few lines can validate a form or toggle a menu. Reaching for React before you can write vanilla JS is paying a complexity tax for a problem you don't have yet.

Accessibility is not optional

Semantic HTML, alt text, sufficient contrast, and keyboard navigation are the difference between "works for me" and "works." Most accessibility failures trace back to skipped semantics in the HTML layer — the free layer.

Real scenarios, real math

  • Personal blog: static site, $10/yr domain, free hosting. Total annual cost ~$10. The only real expense is your writing time.
  • Small business site: static or light CMS, maybe a $0–$20/mo host if you want a dashboard. ~$10–$250/yr.
  • Web app with users: VPS ~$5/mo + domain + maybe a managed database. ~$70–$300/yr before any staff cost.

Tools worth the line item

A code editor (VS Code, free), browser DevTools (free, built in), and Git (free) cover the workflow. Build tools like Vite are free. None of these belong in the recurring-cost column. Pay for them with attention, not money.

Frequently asked questions

Do I need to pay for a website builder?

No. A static site with hand-written HTML/CSS costs about $10/yr for the domain. Builders trade that for convenience and lock-in; pay only if the time saved is worth more than the subscription to you.

Is free hosting reliable enough?

For static sites, GitHub Pages and Netlify free tiers are solid for personal and small business use. Add Cloudflare in front and you get a CDN and DNS at no cost.

When do I need a framework?

When the UI state gets complex — many interactive components sharing data. For a brochure or blog, vanilla JS is enough. Adopt a framework to solve a problem, not to follow a trend.

What about SSL?

Free via Let's Encrypt and auto-renewed by most hosts and Cloudflare. There is no reason to pay for a certificate in 2026.

Model the recurring column before you touch a framework, and you'll spend less and understand more. The caveat: the real cost is your time, not the software — a builder doesn't write your content, it just charges you to open the file.
