The bill that ruins a quarter

A team I know ran what they thought was a small analytics query and got a $14,000 BigQuery invoice for the month. The cause wasn't malice or even a bug — it was a SELECT * over a huge table with no partitioned filter, and BigQuery charges per terabyte scanned. One line of carelessness, one five-figure bill. That single fact tells you more about GCP than any feature list: the power is real, and so is the meter.

Glossary, in plain English

Compute Engine
Virtual machines on Google's infrastructure. You pick a machine type (predefined or custom) and pay per second after the first minute. The f1-micro / e2-micro in eligible regions is part of the always-free tier.
Google Kubernetes Engine (GKE)
Managed Kubernetes. Google originated Kubernetes, and GKE automates cluster upgrades, scaling, and node pools. The control plane is free on the standard tier; you pay for the worker nodes.
BigQuery
Serverless data warehouse. You write SQL; it scans petabytes. On-demand pricing is about $6.25 per TB scanned — so query design directly controls your bill.
Cloud Storage classes
Standard (frequent access), Nearline (~$0.01/GB-month), Coldline, and Archive (cheapest, for rarely read data). Picking the wrong class quietly inflates cost.
VPC
Virtual Private Cloud — your isolated network inside GCP, where you set firewall rules, subnets, and private connectivity.

Myths worth killing

Myth: "GCP is just cheaper than AWS." Sometimes, on sustained usage and data analytics, yes. But "cheaper" isn't a law — it's a per-workload calculation. A lift-and-shift VM fleet can cost about the same across clouds. Model your actual usage.

Myth: "The $300 free credit means I can experiment freely." The credit is real (90 days, new accounts) and useful — but some services bill against it fast (see: that BigQuery story). The always-free tier is separate and persists, but it's narrowly scoped (small VM, limited storage). Read what's actually free.

Myth: "Managed means I don't need to understand it." GKE manages the Kubernetes control plane, not your misconfigured pod requests or your public LoadBalancer. Managed reduces toil; it doesn't remove judgment.

Where GCP genuinely leads

  • Data analytics: BigQuery plus the rest of the data stack (Dataflow, Pub/Sub) is a coherent story few match.
  • Kubernetes maturity: GKE is the reference implementation of Kubernetes for a reason.
  • Networking: Google's backbone is the same one serving Search and YouTube — low-latency global reach.
  • TPUs: Custom ML silicon you can't get from the other two hyperscalers in the same form.

Frequently asked questions

Is GCP easier to start on than AWS?

Many find the console and BigQuery gentler than AWS's breadth. But "easier" depends on what you're building; a pure EC2/S3 shop may find AWS more familiar. Both have free tiers — start there.

How do I avoid a surprise BigQuery bill?

Use partitioned/clustered tables, select only needed columns, set query cost controls and quotas, and preview row counts before full scans. BigQuery's pricing is per-TB-scanned, so query shape is your bill.

Which storage class should I pick?

Standard for hot data, Nearline for monthly access, Coldline/Archive for backups and compliance archives. Moving data to a colder class later is fine, but retrieval fees apply — match the class to access frequency.

Can I run GCP alongside AWS or Azure?

Yes — many shops run multi-cloud. Just don't assume prices or features map 1:1; a "VM" in each cloud differs in billing granularity, support, and networking model.
